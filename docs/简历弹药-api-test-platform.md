# API 自动化测试平台 · 简历弹药（写进简历 + 守得住）

> 用途：把项目压成「能写进简历的 bullet」+ 每个 bullet 的防御深度。深度素材见同目录 `面试弹药-api-test-platform.md`，关源码复现练习见 `关源码复现-api-test-platform.md`。
> ⚠️ **诚实边界（务必先读）**：这个项目代码是「你定需求 + AI 实现」的协作产出。简历上写得出来的功能，面试时**必须能讲清「为什么这么设计」**；讲不清的别写。下面每条都标了深度——带 ✅ 的是你必须自己能答的，带 ⚠️ 的是至少讲清思路、别被问住。

## 一、一句话定位（简历 headline / 自我介绍用）

一个自用接口回归与监控工具：存用例 → 手动 / 定时跑 → 多维度断言（状态码 / 包含 / 耗时 / JSONPath / **响应头**）→ 出报告 → 带账号体系 → 一键容器化部署。技术栈 Fastify5 + Node 内置 SQLite + Vue3/Element Plus + node-cron，**183 测试全绿**。**配套一个「被测系统」office-oa，用这个平台把它测穿了。**

## 二、简历可写的 bullet（每条标防御深度）

1. ✅ **多维度断言 + 自写 JSONPath 求值器（零第三方库）**：断言模型 `expected` 覆盖 `status` / `contains` / `maxTimeMs` / `jsonChecks`；JSONPath 求值器支持 `$.a.b` / `$.arr[0]` / `$.arr[*]` / `.length` 与 8 个比较 op（`eq / ne / gt / gte / lt / lte / contains / exists`）。
   → 讲清：为什么自写（展示能力 + 第三方库对 `*`/`.length` 支持参差），约 60 行更易控、更易测。
2. ✅ **零依赖鉴权：scrypt 加盐哈希 + 手写 HS256 JWT**：不引 `jsonwebtoken`/`bcrypt`；全局 `onRequest` 守卫除白名单（`/health`、登录、注册、静态资源）外强制 `Bearer`，否则 401。
   → 讲清：scrypt 加盐 + `timingSafeEqual` 防时序攻击；JWT 三段结构；verify 三步（拆三段 → 重算签名比对 → 校验 exp）。
3. ⚠️ **node-cron 定时任务 + 重启自动恢复**：cron 表达式 → 到点执行并落执行记录；服务重启遍历 `schedules` 表重新注册，route 增删改后同步启停。
4. ⚠️ **单端口部署**：前端 `web/dist` 由 Fastify 同源托管（`/*` 静态 + SPA 回退），Docker / compose 挂卷持久化 SQLite，无跨域、部署只一个端口。
5. ✅ **测试隔离方案（真实踩坑）**：把 `DB_PATH` 从模块顶层 `const` 改成 `getDb()` 内**惰性解析**，配合 `:memory:` + `setupFiles` 在 import 前注入，根治「测试把用例写进生产库」（早期表现为「全部运行」出现一堆死链 `fetch failed`）。
6. ⚠️ **报告聚合 / 执行记录查询**：`/api/reports/summary` 出总用例 / 总执行 / 通过率 / 按用例统计 / 最近记录。
7. ✅ **被测系统闭环（最值钱的一条，已真跑通）**：平台里有一组 **60 条 OA 用例**，用**用例链**串成一次完整业务闭环 —— 登录抽 token → 建单抽单据 id → 自批 403 → 外部门经理 403 → 本部门经理通过归档 → 归档后「审批人 409 / 无关人 403」成对断言 → 登出后旧 token 401 → 附件边界面（守卫 / 父资源 / 可见性 / body 类型）→ **附件全生命周期（真发 multipart：上传 → 列表 → 下载回读 → 伪装 exe 被拦 → 越权 403/409 成对 → 删除）** → 站内通知（挂钩触发 / 收件人隔离 / 轮次快照 / 标已读幂等）→ **单据导出（响应头 / BOM / 表头 / CSV 公式注入 / 数据范围收敛）**。`npm run test:oa` 打被测系统 **office-oa（15 张表 / 204 条接口测试）**，结果 **60/60 全绿**。**「写了一个被测系统，又用自写平台把它测穿」**，对口测试工程师 / 技术支持岗，比任何功能清单都值钱。闭环全过程与八个真实发现（含「执行器只会发 JSON」「只能看响应体、看不到响应头」这两条能力边界**被发现 → 被补掉**的完整过程）见 `docs/测穿-office-oa-闭环.md`。
8. ✅ **给执行器加请求体类型与文件上传（M8，含一个自己抓出来的前端 bug）**：用例支持 `bodyType`（json / raw / form-data）+ `files`；**multipart 包体手搓不引库**（boundary / CRLF / 二进制安全 / 文件名字段转义），form-data 时**执行器接管 `Content-Type`（带 boundary）与 `Content-Length`**；夹具字节内置在代码里（PNG / PDF / 伪装 exe），因为自动化要的是「每次发一模一样的字节」。
   → 讲清：为什么不用 `form-data` 包（延续零依赖）；为什么要接管 Content-Type（boundary 不可能手填对）；为什么夹具内置而不是让用户传文件（可重复性）。
   → **真机验证时抓到的坑**：从 `/cases/1/edit` 切到 `/cases/new`，Vue 复用组件实例导致 `onMounted` 不重跑、表单残留上一条的 `bodyType` —— 单测和 `vite build` 都不报错，只有真机走一遍才露头（修法 `watch(id, load)` + `resetForm()`）。
9. ✅ **环境变量集（M9）：把被测地址从用例里抽出来**：环境 = `{name, baseUrl, headers, vars}`，用例一律写 `{{base}}/api/xxx`（原来是 44 条 URL 里都烤着 `http://127.0.0.1:3200`，换环境要重写整套用例）；**同一时刻只有一个当前环境**，存在 `settings` 表的**一行 KV** 里，页头有徽标随时可见；环境级默认请求头自动附加到每个请求。
   → 讲清两条优先级：**环境变量是基线、链上 `extract` 抽到的值优先**（基线盖掉事实 = 用过期 token 假装通过）；**环境头是默认值、用例手写的同名头优先**（大小写不敏感）。
   → 讲清为什么当前环境放一行 KV 而不是 `is_active` 列：后者迟早出现「两行都是 active」这种无法自证的状态。
   → **真机验证又抓到一个「会撒谎的徽标」**：徽标画在外壳 `App.vue`、切环境发生在 `Environments.vue`，最初靠「路由变化时重取」对齐 —— 而**在同一页里切环境根本不引起路由变化**，徽标一直显示上一个环境。修法：抽成共享 reactive 状态（`web/src/env.js`，跟 `auth.js` 的 `session` 同一套路）。**一个会撒谎的状态显示，比没有这个显示更危险。**
10. ✅ **执行记录存环境快照，报告能说清「这个通过率是在哪个地址上跑出来的」（M10）**：`runs` 加 `env_name` + `base_url`（**执行当时**的快照），而不是只存 `env_id`；报告新增「按运行环境汇总」，分组键用快照 → 地址改过之后自然分成两组，「换个环境就全红」一眼可见；升级前的老记录归到「(未记录环境)」一组，**不编造**环境名。
    → 讲清为什么不能只存外键：地址改一次（本地 → 预发），历史记录就被**反向改写**成「它从没打过的地址」。**配置是活的，历史是死的** —— 这条和 office-oa 的 `flow_snapshot` 是同一条教训的两次独立出现。
    → 讲清这条是怎么被发现的：M9 刚把地址做成可切换的，一打开报告就答不出「这次打的是谁」。**把值从写死变成可配的那一刻，就要同时问「以后我怎么知道某次运行用的是哪个值」。**
11. ✅ **套件导出 / 导入：让测试资产能带走（M11，含一个端到端测试逼出来的设计缺陷）**：`GET /api/suite/export` 把「用例 + 环境」打成 JSON，`POST /api/suite/import` 吃回去；导入支持 `rename`（默认，两个都留）/ `overwrite` / `skip` 三种冲突策略；坏文件 400 说清原因，**坏条目只记进 `failed`、其余照常导入**。
    → 讲清三个设计点：**不带 id**（本地自增，跨库无意义）、**导出顺序 = 串链顺序**（`listCases()` 是倒序的，直接导出会让导入后的链**静默断掉** —— 用例照跑、只是全红）、**敏感头脱敏**（导出文件天生要被分享）。
    → 讲清脱敏的判据是「键名敏感 **且** 值是字面量」：`Authorization: Bearer abc123` 要抹，`X-Token: {{token}}` 要带 —— 后者是运行期从链上取的**占位符**，抹了只会断链、不会更安全。
    → ⭐ **这个缺陷是端到端用例先红的**：第一版按键名抹，跑「导出 → 清空库 → 导入 → 再跑一遍全绿」时第二条用例不带 token、断言红。**只写单元测试验证 `redactHeaders` 的输入输出，这个坑会一直藏着** —— 因为它问的是「规则本身对不对」，不是「实现对不对」。
12. ✅ **用例分组（M12）：给「几十上百条用例」一个可读的节奏**：`test_cases` 加一列 `group`（业务标签），落成四件事 —— 列表 `?group=` 筛选、`POST /api/run-all {group}` 按组跑、报告新增「按分组汇总」(`byGroup`)、套件导出导入带上 `group`。
    → 讲清两个刻意的边界：**分组只是标签，不是实体**（纯字符串列，不建外键/枚举表 —— 硬上外键是把「标签」做成「分类体系」）；**分组不改断言、不动串链顺序**（`run-all` 仍然先按 id 升序排再按组筛），过滤复用已有的 `prefix / ids` 入口，不为分组另开一条运行路径。
    → 讲清「按组运行」的价值边界：**单个分组未必是自包含的链** —— 「审批引擎」那组依赖「登录」抽出的 token，单独跑会红。分组的作用是「按主题跑一坨 + 报告按主题看」，不是替你切链。
13. ✅ **删用例的连带清理（M13，被我自己写的真机脚本绊出来的）**：`runs.case_id` / `schedules.case_id` **都不是外键**，而三条删用例的路径（`deleteCase` + `npm run seed` + `npm run seed:oa`）都不管派生数据；`seed:oa` 每次重跑都先删旧用例 → 报告里积了 **791 条**没有名字的「用例#id」，而且只会越来越多。
    → 讲清修法的关键不是「补一句 DELETE」，而是**收口**：删除收到 `deleteCase` **一处**、在同一事务里连带清 `runs` + `schedules`；⚠️ **删库行不会自动停内存里的 cron**，所以把被删的 `scheduleIds` **回传给路由**去停；用例不存在时**整笔回滚**，不误删恰好指向该 id 的历史。
    → 讲清 UX 一侧：接口把连带条数如实回传（`{deleted, runsDeleted, schedulesDeleted}`），前端提示「已删除（连带 3 条执行记录）」—— **静默毁掉几十条历史，比多说一句话危险**。
    → 一句话总结：**「删实体」和「删它产生的影响」是两件事**（同源教训：环境→历史快照、流程模板→在途单据）。另附 `npm run clean:orphans` 扫尾历史遗留（默认只报告，删完复查「剩余 0 条」）。
14. ✅ **响应头断言（M14，第二次「能力边界被真实需求逼出来」）**：`expected` 新增 `headers = [{name, op, value}]`（头名**大小写不敏感**，`op` 复用已有的 `eq / contains / exists`，不新造一套）；执行器开始读 `res.headers`；编辑器补「响应头断言」编辑区。
    → 讲清它是怎么来的：给 office-oa 开「单据导出 CSV」这一面时，发现「导出的对不对」有一半答案在**响应头**里（`Content-Type` / `Content-Disposition` / BOM），而平台的执行器**只读 `res.text()`、从不碰 `res.headers`** —— 这类断言**一个字都写不出来**。和 M8 的 multipart 同源（那次在**请求侧**，这次在**响应侧**）。
    → ⭐ 讲清第二处更阴的：补完头还不够，**BOM 依然断言不了**，因为 `fetch` 的 `res.text()` 按规范会**吃掉开头的 BOM**（而且**静默**：不报错，只会永远红，断言方向写反了甚至假绿）。修法：绕开 `res.text()`、按 `arrayBuffer()` 自己解码。
    → 一句话总结：**能力边界不是设计出来的，是被一个真实需求逼出来的；而消掉它的方式是在代码里补，不是在文档里改口。**

## 四、高频深挖题（精选，详答见 `面试弹药-api-test-platform.md`）

1. **为什么 `node:sqlite` 不引 `better-sqlite3`？** → 零原生编译模块，CI / Docker / 跨平台无编译坑。
2. **scrypt 和 bcrypt 比怎么样？** → Node 内置 `crypto` 就有 scrypt，零依赖；重点是「加盐 + `timingSafeEqual` 防时序攻击」，不是非得 bcrypt。
3. **手写 JWT 而不是 `jsonwebtoken`？** → HS256 = `base64url(header).base64url(payload).HMAC-SHA256`；verify 三步走：拆 3 段 → 重算签名比对（`timingSafeEqual`）→ 校验 `exp`。
4. **JSONPath 求值器怎么实现的？** → 路径分词成 steps（field / index / wild），从 root 出发逐 step 收集「匹配值数组」；`[*]` 把数组元素展开；`.length` 处理数组长度；无匹配提前终止返回 `[]`。
5. **定时任务重启怎么恢复？** → `startScheduler()` 启动时遍历 `schedules` 表 `registerJob`；route 增删改后 `refreshJob` 同步注册 / 停用。
6. **测试怎么不污染生产库？** → DB 路径惰性解析 + `:memory:` + `setupFiles` 在 import 前注入；每个测试文件各自一份内存库。
7. **你的测试平台能测「需要登录的接口」吗？上传文件呢？** → 两个都踩过：
   前者靠**用例链**（`{{var}}` + `extract` + run-all 共享内存变量袋）；
   后者一开始**不能**（执行器只会 `JSON.stringify(body)`），我把这条边界写进文档，后来当成工作项做掉了（M8：`bodyType=form-data` + 手搓 multipart + 内置夹具）。
   → 这类问题答「我的工具边界在哪、我怎么发现的、我怎么补的」，比答「都能测」可信得多。
8. **手搓 multipart 要注意什么？** → boundary 要用一段**不会出现在内容里**的随机串；每段之间是 CRLF，结尾必须再补一个 `--boundary--`；
   `Content-Type` 必须带 `boundary=` 参数（所以不能沿用用例里手填的那个）；请求体是二进制，`Content-Length` 自己算比让运行时猜稳。
9. **夹具为什么要内置在代码里？** → 自动化要**可重复**：每次跑发一模一样的字节，`size == 41`、`contains 某段正文` 这类断言才立得住；
   让用户传一个本地文件，换个机器就红，等于把回归测试变成一次性脚本。
10. **环境变量和用例链抽到的变量，谁优先？** → **链上抽到的优先**。环境是「你去哪」（基线），extract 是「本次链上刚发生的事实」
   （比如刚登录拿到的 token）；让基线盖掉事实，就等于拿过期 token 假装通过。
11. **「当前环境」这种全局唯一状态怎么存？** → 存 `settings` 表的**一行 KV**（`active_env_id`），不在 `environments` 上加 `is_active` 列 ——
   一行 KV 天然保证「只有一个」，而布尔列迟早出现「两行都是 active」这种无法自证的状态。
12. **环境切换会影响定时任务吗？** → 不会「跑偏」：单跑 / run-all / 定时三条路径都走 `runner.runCase`，环境在**那一处**统一注入。
   这是刻意的 —— 如果只在手动运行里注入环境，就会出现「手动跑用环境、定时跑不用」这种最难查的偏差。
13. **你的真机验证脚本自己踩过什么坑？** → 往 localStorage 写了 token 却还是被弹回登录页。两个原因叠一起：
   ① `auth.js` 的 `session.token` 是**模块加载时**读一次 localStorage 的，只写不重载 → session 还是空的 → axios 不带 `Authorization` → 401 → 拦截器 `clearSession()` 把刚写的 token 抹掉；
   ② `Page.reload` 是异步的，紧接着发 `Page.navigate` 会跟重载竞态。**现象是「token 明明写了却不见了」**，不打印现场基本查不出来。
14. **报告的通过率能不能只看总数？** → 不能。同一组用例跨了两个环境时，混在一起的平均值会掩盖「换个环境就全红」。
   所以报告要按**环境快照**分组：本地 100%、预发 0% 一眼可见，而不是一个看不出问题的 50%。

## 五、一句话收尾（被问「最大难点 / 最得意」时）

> 「最大难点是**让测试不污染生产数据**——ESM 模块顶层快照环境变量导致 `:memory:` 永不生效，改成惰性解析才根治。这让我理解了模块加载时序对全局配置的影响。」

> 备用、最亮眼的一句（被问到这个项目哪里不一样时）：「它最不一样的点是本身就配了一个**被测系统**——我用自写的测试平台把另一个项目测穿了。测试岗看这个闭环，比看任何功能清单都值钱。」

> ⚠️ 诚实提示：以上功能里，**「我从报错里自己改出来的」有这几条** —— ① 测试隔离坑（ESM 顶层快照导致 `:memory:` 不生效）；
