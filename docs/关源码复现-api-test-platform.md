## 练习清单（12 题 + 1 组附加画图）

> **怎么用**：关掉源码（别偷看），在空白编辑器或纸上写；写完再打开真实文件 diff。
> ⭐ 越多 = 越该先练。每题都标了对照的**文件 / 函数**。

### ⭐⭐ 1. 自写 JSONPath 求值器 —— `jsonPathGet()`
> 对照 `src/jsonpath.js`：`jsonPathGet()` + `parsePath()` + `applyStep()`

任务：**不引任何库**，写出一个能吃 `$.data.list[0].name` / `$.items[*].id` / `$.data.list.length`
的求值器，返回**匹配值数组**，无匹配返回 `[]`。

要能答的三个「为什么」：
- 为什么返回**数组**而不是单值？
- `parsePath` 遇到**不认识的字符**为什么是 `i++` 跳过，而不是抛错？
- `.length` 为什么**只在数组上**才特殊处理？

### 2. 断言引擎 —— 4 类断言 + 8 个操作符
> 对照 `src/runner.js`：`runCase()` 的断言段（约 70–106 行）+ `evalJsonCheck()`（约 183–204 行）

任务：写出 `expected` 的四类断言判定 —— `status`（状态码相等）/ `contains`（响应原文含子串）/
`maxTimeMs`（耗时上限）/ `jsonChecks`（JSONPath 字段断言）；再写出 8 个 op：
`eq / ne / gt / gte / lt / lte / contains / exists`。

**必须讲清的一条语义**（面试高频）：用了 `[*]` 产生多匹配时 ——
`contains` = **任一命中**，`exists` = 有没有匹配，其余 op = 取**首个**匹配值。
追问会来：「为什么不干脆全部『任一』，或者全部『首个』？」

### 3. 模板替换 —— `renderTemplate()`
> 对照 `src/vars.js`：`renderTemplate()`

任务：写出 `{{var}}` 的递归替换（字符串 / 数组 / 对象都要能穿透），返回 `{value, missing}`。

三个易错点：
- 变量**缺失时替换成什么**？为什么是空串，而不是原样保留 `{{token}}`？
- `missing` 为什么要**去重**？
- 变量缺失为什么**不直接判用例失败**？（先想：请求本身会不会失败？）

### 4. 变量抽取 + 两条优先级 —— `applyExtract()`
> 对照 `src/vars.js`：`applyExtract()` / `createVarBag()`

任务：从**本用例的响应**里按 `extract:[{name,path}]` 抽值进变量袋；值统一转成字符串（要能塞进 header）。

必须讲清的两条**优先级**（背下来）：
- 环境变量 **vs** 链上 extract 抽到的值 → 谁优先？为什么？
- 环境头 **vs** 用例里手写的同名头 → 谁优先？为什么？

### 5. 用例链为什么必须顺序跑 —— `runAll()`
> 对照 `src/runner.js`：`runAll()`（约 223 行起）

任务：写出批量执行循环，并讲清「**为什么这里绝不能改成 `Promise.all`**」。
再答一个问题：变量袋的**生命周期** —— 一次 run-all 一个袋子？跨运行复用行不行？

### 6. 手写 HS256 JWT —— `signToken()` / `verifyToken()`

任务：只用 `node:crypto` 写出 `signToken(payload)` 与 `verifyToken(token)`。

- 三段分别是什么？`base64url` 和 `base64` 差在哪（要替换哪些字符、要不要去 `=`）？
- `verifyToken` 的**四步校验顺序**是什么？哪一步用 `timingSafeEqual`，为什么？
- `exp` 在第几步校验？

### 7. 密码哈希 —— `hashPassword()` / `verifyPassword()`
> 对照 `src/auth.js`

任务：用 `crypto.scrypt` 加盐哈希，存成 `salt:hash`；verify 用 `timingSafeEqual` 比对。
易错点：**长度不一致时为什么要提前 `return false`**？（不这么做，`timingSafeEqual` 会怎样？）

### 8. 套件导出的脱敏判据 —— `redactHeaders()`
> 对照 `src/suite.js`：`redactHeaders()` / `isSensitiveHeader()` / `hasTemplatePlaceholder()`

任务：写出脱敏函数，判据是「**键名敏感 _且_ 值是字面量**」。

再追问一句：导入方向为什么还要单独写一个 `dropBlankSensitive()`？

### 9. 删用例的连带清理 —— `deleteCase()`（M13）
> 对照 `src/cases.js`：`deleteCase()` + `index.js` 的 `DELETE /api/cases/:id`

任务：写出「删一条用例，连带删掉它**产生**的一切」（`runs` + `schedules`），
返回 `{deleted, runsDeleted, scheduleIds}`。

三个必须讲清的点：
- 为什么删了库里的行**不会自动停掉内存里的 cron**？所以路由层拿到 `scheduleIds` 之后要做什么？
- 用例**不存在**时为什么必须**整笔回滚**（不能顺手删掉恰好指向这个 id 的历史数据）？
- 为什么要把连带条数**回传给前端**？

### 10. 手搓 multipart/form-data 包体
> 对照 `src/multipart.js`

任务：不引库，手写一个 `multipart/form-data` 请求体（含 boundary）。

要能讲清：boundary 怎么选（为什么要一段「不会出现在内容里的随机串」）、每段之间的 CRLF、
**结尾为什么还要再来一个 `--boundary--`**、为什么执行器必须**接管** `Content-Type`（并覆盖用例里手填的那个）、
`Content-Length` 为什么要自己算而不是让运行时猜。

### 11. 响应头断言 + 为什么 BOM 断言不了（M14）
> 对照 `src/runner.js`：读 `res.headers` 的那几行 + `applyExtract` 附近的**响应解码**；`web/src/views/CaseEditor.vue` 的「响应头断言」编辑区

任务：写出「给用例加一类**响应头断言**」要做哪两件事，并回答一个看起来矛盾的追问。

- 两件事：① 执行器读响应头、摊平成**小写键**（为什么？）；② `expected` 加 `headers = [{name, op, value}]`，
  `op` **复用**已有的 `eq/contains/exists`（为什么不新造一套？）。
- ⭐ 追问：**「你已经能读头了，为什么『导出必须带 BOM』还是断言不了？」**
  答：因为 `fetch` 的 `res.text()` 按规范会**吃掉响应体开头的 BOM** —— 所以还得**绕开 `res.text()`**，
  用 `res.arrayBuffer()` 自己按 UTF-8 解码。要说得出这件事为什么**危险**：它不报错，只是永远红；
  **断言方向写反了甚至会假绿**。
- ⭐⭐ 把这条上升成检查项：**凡是「验字节」的断言，先问中间有没有哪个标准库替我做了一次我不想要的清洗。**

### 12. 分组定时任务（M15）
> 对照 `src/scheduler.js`：`runScheduledJob()` + `registerJob()` 的 cron 回调；`src/schedules.js`：`createSchedule` 的 group 优先分支；`src/db.js`：schedules 表 `case_id` 可空 + 新增 `group` 列

任务：写出「让一个 cron 跑一整组用例」要动哪几处，并回答一个设计追问。

- 三处改动：① `schedules` 表 `case_id` 改**可空** + 加 `group` 列（为什么可空，而不是另建一张 `group_schedules` 表？）；
  ② `createSchedule` 里 `group` **优先于** `caseId`（二选一），空组 / 缺参直接 400（为什么？）；
  ③ 把 `runScheduledJob` 从 cron 回调里**抽出来** —— group 时调 `runAll(listCases(group).sort(by id))` **复用同一条链引擎**，单条时退回 `runCase`。
- ⭐ 追问：**「删一条用例时，分组定时任务会不会变成孤儿？」**
  答：不会。分组任务用**哨兵 `case_id = 0`** 表示，而 `deleteCase` 是「按真实 `case_id` 删」——`0` 永远匹配不到任何真实用例，
  所以删单条用例清不掉分组任务。这比「建外键 + 级联」轻：不用重建表（`case_id` 在新库仍是 `NOT NULL`），
  且空组在创建时就被 400 拦掉（**杜绝「定时任务静默空跑」**）。
- ⭐⭐ 把这条上升成检查项：**「我加的新维度（group）会不会和已有删除逻辑（deleteCase）打架？」** —— 设计哨兵值比加级联约束更省事、也更不易漏。

## 我的示范轮（以第 1 题为例）

> 我做给你看「能写出来长什么样」。下面是**标准答案，可直接拿去跟你的默写做 diff** ——
> 内容是**代码里的真实逻辑**（`src/jsonpath.js`），不是「某个人凭记忆写出来的版本」。

**整体骨架：一个循环 + 两个纯函数**

| 步 | 做什么 | 为什么在这一步（想不清就容易写错的地方） |
|---|---|---|
| 0 | 守卫：`pathStr` 是 `null` / 空串 → 直接返回 `[]` | 空路径不是「根」，是「**没给路径**」；返回根会让人误以为匹配到了东西 |
| 1 | `parsePath(p)` 把字符串切成 steps | 分词独立出去，主函数就只剩「逐 step 走」一件事 |
| 2 | `let cur = [root]` | **从数组开始、每一步都数组进数组出**，是全集设计的关键；有了它，`[*]` 才不是特例 |
| 3 | 逐 step：`next = []`，`for (const v of cur) applyStep(v, step, next)` | 每个当前值**各自**展开 —— `$.a[*].b` 才能从多个 `a` 里各取 `b` |
| 4 | `cur = next`；若 `cur.length === 0` → **提前** `return []` | 路径无匹配是**正常结果**，不是错误，所以提前终止而不是抛错 |
| 5 | 返回 `cur` | 返回**数组**，把「取首个」的决定权留给调用方 |

**分词 `parsePath`（状态机，只认 4 种字符）**

| 遇到 | 产出 step | 细节 |
|---|---|---|
| `$` | 不产出 | 只吃开头这一个；`let i = p[0] === '$' ? 1 : 0` |
| `.` | `{type:'field', name}` | 一直读到下一个 `.` 或 `[` 为止（名字可为空串，不崩即可） |
| `[` | 取决于内容 | 首字符是 `'` / `"` → 去首尾引号当 `field`；`*` → `wild`；否则 `Number(inner)` 当 `index`（`i = j + 1` 跳过 `]`） |
| 其它 | 不产出 | `i++` **跳过**（容错优先，不抛错） |

**求值 `applyStep(v, step, out)`**

| type | 行为 | 为什么这么写 |
|---|---|---|
| `field` | 先判 `step.name === 'length' && Array.isArray(v)` → `out.push(v.length)`；否则**对象自有属性**才 push `v[name]` | `.length` 只在数组上特殊处理 —— 对象上的普通 `length` 字段该走正常取值，不能混淆 |
| `index` | `Array.isArray(v)` 且 `Number.isInteger(index)` 且 `0 <= index < v.length` → push | 越界 / 负数 / `NaN` 一律视为**无匹配**，静默跳过 |
| `wild` | `Array.isArray(v)` → 逐个 push | 不是数组就无匹配，也不报错 |

**三个「为什么」的答案**

1. **为什么返回数组？** `[*]` 天然一对多。返回数组，调用方才能自己决定：取首个（`jsonPathFirst()`）还是
   「任一命中即通过」（`contains` 断言）。这是**把决定权留在正确的层**。
2. **为什么跳过不认识的字 `i++` 而不是抛错？** 路径是人手敲的，容错比报错友好。真正的错误（路径不对）
   会如实体现成「无匹配 `[]`」，不需要额外抛错来表达。
3. **为什么 `.length` 只在数组上生效？** 因为 `arr.length` 是求值器要提供的**便捷语义**；
   而 `{length: 5}` 里的 `length` 只是个普通字段，两者不能混。

**明确不做（文件头注释里写死的）**：过滤器 `[?()]`、递归 `..`、切片 `[1:3]`、当前节点 `@`。
→ 能讲清「**为什么不做**」比「做了多少」更像懂行：这些都要实现一套**表达式求值**，边界会指数级膨胀，而断言场景用不到。

对照真实代码（`src/jsonpath.js`）：**一致 ✅**。
