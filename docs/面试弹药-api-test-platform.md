# API 自动化测试平台 · 面试弹药（我改过的点 + 为什么）

> 用途：面试「测试工程师 / 技术支持工程师」时讲这个项目用。
> ⚠️ **诚实边界（务必先读）**：这个项目代码是「你定需求 + AI 实现」协作产出。面试时**绝对不能**装成「全独立手写」。正确讲法：**需求是我定的，关键技术点我逐条复现、能讲清为什么这么设计**。下面每个点都标了「你需不需要能独立写出来」——带 ✅ 的是你必须自己能答的，带 ⚠️ 的是你至少能讲清思路、别被问住。

## 一、一句话定位（背这句）
一个能「存接口用例 → 手动/定时跑 → 多维度断言 → 出报告 → 带账号体系 → 一键容器化部署」的自用接口回归/监控工具。技术栈：Fastify5 + Node 内置 SQLite + Vue3/Element Plus + node-cron，**132 个测试全绿**。
**并且用这个平台把自己写的另一个系统 office-oa 测穿了**（52 条用例串成一条业务链，`npm run test:oa` → 52/52）。

## 二、9 个技术亮点（可直接展开）

### 1. 多维度断言 + 自写 JSONPath 求值器 ✅
- 断言模型 `expected`：`status`（状态码）/ `contains`（响应体包含）/ `maxTimeMs`（耗时上限）/ `jsonChecks`（JSONPath 字段值断言）。
- `jsonChecks` 支持 8 个 op：`eq / ne / gt / gte / lt / lte / contains / exists`。
- JSONPath 求值器**完全自写、零第三方库**，支持 `$.a.b`、`$.arr[0]`、`$.arr[*]`、`.length`。
- **为什么自己写而不用 `jsonpath` 库？** 项目定位就是「手写轮子展示能力」；且第三方库对 `$.arr[*]`、`.length` 这类写法支持参差，自写约 60 行更可控、更易测（有 70 个单测兜底）。

### 2. 零依赖鉴权（scrypt 哈希 + 手写 HS256 JWT）✅
- 密码：`crypto.scrypt` 加盐哈希 + `timingSafeEqual` 防时序攻击（盐与密文同存）。
- Token：手写 HS256 = `base64url(header).base64url(payload).HMAC-SHA256`，不引 `jsonwebtoken`。
- 全局 `onRequest` 守卫：除 `/health`、登录、注册、静态资源外，所有 `/api` 必须带 `Bearer`，否则 401。
- **为什么零依赖？** 不引 `bcrypt`/`jsonwebtoken`，跨平台/CI/Docker 无原生编译坑，也正好展示密码学基础。

### 3. 测试隔离踩坑（真实复盘）✅⚠️
- 早期把 `DB_PATH` 写成模块顶层 `const`，导致 `tests/setup.js` 里 `DB_PATH=:memory:` 在 import 之后才设、**永不生效**，测试把用例写进了真实库（表现为「全部运行」出现一堆死链 `fetch failed`）。
- 修法：DB 路径改为 `getDb()` 内**惰性解析**，配合 `setupFiles` 在 import 前注入 `:memory:`，彻底隔离。
- **这是面试官最爱问的「你遇到过什么坑」素材**，必须能讲清因果。

### 4. 单端口部署 + SPA 回退
- 前端 `web/dist` 构建后由 Fastify 同源托管（`/*` 静态 + SPA 回退），部署只一个端口、无跨域。
- 提供 Dockerfile + docker-compose，挂卷持久化 SQLite。

### 5. 用例链：让「需要登录的接口」能被自动测 ✅
- 原来的引擎一次只发一个请求 → 登录拿到的 token 传不到下一个用例 → **凡是要鉴权的接口一条都测不了**。
- 补的最小集合：`{{var}}` 占位（url/headers/body/文件名）+ `extract:[{name,path}]` 按 JSONPath 从**本用例响应**抽值 + 「全部运行」按**创建顺序**串链并共享一个变量袋 + `{prefix}` 只跑一组。
- **变量袋只在内存、不落库**（token 不该进库、也不该跨运行复用，否则会拿过期 token 假装通过）；变量缺失**不判失败**但 detail 里点名。
- **必须顺序跑**：改成 `Promise.all` 就断了链 —— 代码里专门有一行注释钉住这件事。

### 6. 手搓 multipart/form-data ✅⚠️
- 原来执行器只会 `JSON.stringify(body)`，**发不出文件上传**。这条边界我先写进文档，下一轮当成工作项在代码里消掉了。
- `boundary` 生成、CRLF 与结尾 `--boundary--`、**二进制安全**、文件名字段引号转义 + 去换行，全手写、不引库。
- form-data 时执行器**接管** `Content-Type`（带 boundary）与 `Content-Length`，并覆盖用例里手填的那个（大小写不敏感去重）。
- 夹具字节**内置在代码里**（PNG/PDF/伪装 exe），不让用户传文件 —— 自动化要的是「每次发一模一样的字节」，`size == 41` 这种断言才成立。

### 7. 环境变量集：把「打谁」从用例里拿出来 ✅
- 环境 = `{name, baseUrl, headers, vars}`，用例里写 `{{base}}`；**同一时刻只有一个当前环境**，存在 `settings` 的**一行 KV** 里，而不是给 environments 加 `is_active` 列（后者迟早出现「两行都 active」）。
- 两条优先级要能张口就来：**环境变量是基线，链上 extract 抽到的值优先**；**环境头是默认值，用例手写的同名头优先**。
- 三条运行路径（单跑 / run-all / 定时）都走 `runner.runCase`，所以环境只在一处生效。

### 8. 执行记录存环境快照：配置是活的，历史是死的 ✅
- M9 把地址变成可配的，紧跟着报告就答不出「这次跑在哪个环境」—— 在地址写死的年代这不是问题（只有一个地址），
  地址一变可配，**每条不写清「当时用的是哪个值」的历史记录都不可解释**（跨了两个环境的 92% 通过率，什么都不能说明）。
- 修法是在 `runs` 里**存快照**（`env_name` + `base_url`），而不是只存 `env_id`：
  只存外键的话，地址改一次（本地 → 预发）历史就被**反向改写**成「它从没打过的地址」。
- 报告加「按运行环境汇总」，分组键用快照 → 地址改过之后自然分成两组，「换个环境就全红」一眼可见。
- 老记录归到「(未记录环境)」一组，**不编造**环境名（本机实测 557 条）。
- 这和 office-oa 的 `flow_snapshot`（改流程模板不影响在途单据）是同一条教训的两次独立出现。

### 9. 套件导出导入：让测试资产真的能带走 ✅⚠️
- 52 条用例链跑通之后，它是**长在这个库里的** —— 发人、换机器、上 CI 都只能重新 seed。
  **资产带不走就是本地状态。** 于是做了 `GET /api/suite/export` / `POST /api/suite/import`。
- 三个设计点：**不带 id**（本地自增，跨库无意义，带过去串链会错位）；
  **导出顺序 = 串链顺序**（`listCases()` 是倒序的，直接导出会让导入后的链**静默断掉** —— 用例照跑、只是全红，比报错难查）；
  **敏感头脱敏**（导出文件天生要被分享）。
- 脱敏的判据是「键名敏感 **且** 值是字面量」—— `X-Token: {{token}}` 是**变量引用**，抹了只会断链、不会更安全。
  ⭐ 这条不是我推出来的，是「导出 → 清空库 → 导入 → 再跑一遍全绿」的端到端用例**先红了**才回头改的。
- 导入侧两条「别一刀切」的约定：**坏文件 400、坏条目继续**（51/52 的文件不该因为第 52 条被整份打回）；
  **冲突默认 `rename`**（两个都留），既不悄悄丢你的数据，也不悄悄盖你的数据。

## 四、高频深挖题 + 参考答案（先理解再背）
1. **为什么用 `node:sqlite` 不引 `better-sqlite3`？** → 零原生编译模块，CI/Docker/不同平台无编译坑。
2. **scrypt 和 bcrypt/argon2 比怎么样？** → Node 内置 `crypto` 就有 scrypt，零依赖；重点是「加盐 + timingSafeEqual 防时序攻击」，不是非得 bcrypt。
3. **手写 JWT 而不是 `jsonwebtoken`？** → 展示能力 + 零依赖；HS256 结构 = base64url(header).base64url(payload).HMAC-SHA256；verify 三步走：拆 3 段 → 重算签名比对（timingSafeEqual）→ 校验 exp。
4. **JSONPath 求值器怎么实现的？** → 路径分词成 steps（field/index/wild），从 root 出发逐 step 收集「匹配值数组」；`[*]` 把数组元素展开；`.length` 处理数组长度；无匹配提前终止返回 []。
5. **定时任务重启怎么恢复？** → `startScheduler()` 启动时遍历 `schedules` 表 `registerJob`；route 增删改后 `refreshJob` 同步注册/停用。
6. **测试怎么不污染生产库？** → DB 路径惰性解析 + `:memory:` + `setupFiles` 在 import 前注入。
7. **用例链为什么要顺序跑？** → 后面的用例依赖前面 `extract` 出来的变量（token / 主键），并发跑就没有「前面」了；变量袋是整轮共享的一个对象，顺序是它的前提。
8. **`$.arr[*]` 上的 `contains` 应该是什么语义？** → **任一命中**。这条是拿真系统测出来的：权限数组里断言「有 user:read」，若只看首个匹配就会因为第一个是 `announcement:write` 而假失败。
9. **upload 这种 multipart 请求，为什么 `Content-Type` 不能由用例填？** → 必须带执行器自己生成的 `boundary`，否则服务端解不出分段；所以执行器**覆盖**它（同时自己算 `Content-Length`，请求体是二进制，别让运行时去猜）。
10. **报告为什么要记「运行环境」，只记一个环境 id 不够吗？** → 不够。环境是可以被编辑的：改一次地址，只存 id 的话历史记录就被反向改写成了「它从没打过的地址」。存快照（名字 + 地址）才能保证「那次实际打的是谁」永远查得到。**配置是活的，历史是死的。**
11. **升级之后的老记录怎么办？** → 不给它们编一个环境名，单列一组「(未记录环境)」。**把缺失如实显示出来，比补一个看起来合理的默认值安全** —— 编出来的默认值会被当成事实。
12. **导出用例时，怎么决定哪些请求头要脱敏？** → 判据不是「键名敏感就抹」，而是「键名敏感 **且** 值是字面量」。
    `Authorization: Bearer abc123` 要抹（那是真凭据）；`X-Token: {{token}}` 要原样带出去（那是运行期从链上取的占位符）。
    这个区别是被端到端用例逼出来的：第一版按键名抹，结果导入后第二条用例不带 token，链断了。
13. **导出文件里为什么不带 id？** → id 是**本地自增**的，换一个库就指向别的东西了。更关键的是：用例链靠「前一条抽变量、后一条用变量」串起来，
    带 id 过去、导入时又重排了顺序的话，链条会错位。所以文件里只保留「顺序」这一件事（数组顺序 = 创建顺序 = 串链顺序），id 由导入端重新分配。

## 五、一句话收尾（被问「这项目最大难点」时）
「最大难点是**让测试不污染生产数据**——ESM 模块顶层快照环境变量导致 `:memory:` 永不生效，改成惰性解析才根治。这让我理解了模块加载时序对全局配置的影响。」

> 备用收尾（如果面试官更关注「你到底测出过什么」）：
> 「更值钱的是**这套工具自己被真系统抓出来的毛病**。我把 office-oa 的 52 条用例串成一条链去跑，
> 红的第一条不是被测系统，是我的断言引擎 —— 多匹配 `contains` 只看第一个值。
> 后来还有一条：变量缺失的提示被 catch 分支吃掉了，**最需要提示的人恰好收不到提示**。
> 这些让我明白：工具报红的时候，先分清是『被测系统的 bug』还是『我的工具在撒谎』。」
