# API 自动化测试平台 · 项目全讲

> 面向全栈 / 测试运维岗位的简历项目。一句话：一个能「存接口用例 → 手动/定时跑 → 出报告 → 带账号体系 → 一键部署」的自用接口监控与回归测试工具。
> 本文既是给面试官看的「项目讲解」，也可直接当作作品集博客发布。M1–M10 已完成，113 个自动化测试全绿，
> 并且**用这个平台把另一个自写项目 office-oa 测穿了**（44 条用例串成一条业务链，`npm run test:oa` → 44/44）。

---

## 1. 这个项目解决什么问题

实习时每天要手动点一堆接口，确认采集脚本没挂、返回格式没变。十几个接口一个个 Postman 点，既慢又容易漏。于是想做一个**自己的轻量版接口监控**：

- 把要盯的接口（URL + 期望结果）录进去；
- 点一下「全部运行」就挨个打过去，告诉我哪几个挂了、哪几个返回的字段不对；
- 还能设个 cron，每天定时自己跑，不用我动手；
- 跑完出报告，看通过率、看哪条接口最不靠谱。

和 Postman / JMeter 的区别：**零运维、零外部依赖、单文件数据库、自带账号体系和前端界面**，能直接 `docker compose up` 扔到服务器上给小团队用。

## 2. 架构

```
┌─────────────── 浏览器 (Vue3 + Element Plus) ───────────────┐
│  登录页 / 用例列表 / 请求编辑器 / 运行结果 / 报告+定时任务管理   │
└───────────────────────────┬────────────────────────────────┘
                            │  axios（自动带 Bearer token）
                            ▼
┌──────────── Fastify 后端（单端口 :3001）───────────────────┐
│  鉴权守卫 onRequest（Bearer 校验）                          │
│  /api/auth/*        注册/登录/me/改密                        │
│  /api/cases/*       用例 CRUD + 单条运行                    │
│  /api/run-all       全部运行汇总（支持按前缀只跑一组）        │
│  /api/schedules/*   定时任务 CRUD（node-cron）              │
│  /api/reports/*     报告聚合                                │
│  /api/environments/* 环境变量集 + 当前环境（M9）              │
│  /*                 生产环境同源托管 web/dist（SPA 回退）      │
│                                                            │
│  执行引擎 runner.js  →  发请求 + 多维度断言 + 变量渲染/抽取    │
│  请求体组装 bodyTypes/multipart/fixtures.js（M8）           │
│  变量链 vars.js + 环境注入 environments.js（M7/M9）          │
│  自写 JSONPath 求值器 jsonpath.js                           │
│  鉴权核心 auth.js    →  scrypt 哈希 + 手写 HS256 JWT         │
└───────────────────────────┬────────────────────────────────┘
                            ▼
                  node:sqlite（零原生依赖，data/app.db）
```

**关键取舍**：数据库用 Node 22 内置的 `node:sqlite`，不引任何原生编译模块（如 `better-sqlite3`），避免 CI / Docker / 不同平台上的编译坑。鉴权同样零依赖——密码哈希用内置 `crypto.scrypt`，Token 用手写 HS256 JWT，不引 `jsonwebtoken`。**multipart 包体也是手搓的**（M8），不引 `form-data` / `busboy`。

## 3. 技术亮点（面试可展开）

### 3.1 多维度断言 + 自写 JSONPath 求值器
断言模型 `expected`：
```json
{
  "status": 200,
  "contains": "ok",
  "maxTimeMs": 5000,
  "jsonChecks": [
    { "path": "$.data.total", "op": "gte", "value": 1 },
    { "path": "$.items[0].id", "op": "exists", "value": true }
  ]
}
```
支持：状态码、响应体包含、耗时上限、JSONPath 字段值（`eq/ne/gt/gte/lt/lte/contains/exists`）。

JSONPath 求值器**完全自写**，未用第三方库，支持 `$.a.b`、`$.arr[0]`、`$.arr[*]`、`.length`。核心逻辑（节选）：
```js
// src/jsonpath.js —— 极简路径求值，按 . 切分、[] 取下标、* 展开
function resolve(root, path) {
  const segs = path.replace(/^\$\.?/, '').split('.')
    .flatMap((s) => s.split('[').map((x) => x.replace(']', '')))
    .filter(Boolean)
  let cur = root
  for (const seg of segs) {
    if (cur == null) return undefined
    if (seg === '*' && Array.isArray(cur)) { cur = cur.flatMap((v) => Object.values(v)); continue }
    if (/^\d+$/.test(seg)) cur = cur[Number(seg)]
    else cur = cur[seg]
  }
  return cur
}
```
> 为什么自己写而不用 `jsonpath` 库？项目定位就是「手写轮子展示能力」，且第三方库对 `$.arr[*]`、`.length` 这类写法支持参差，自写 60 行更可控、更易测。

### 3.2 零依赖鉴权（scrypt + 手写 HS256 JWT）
密码哈希（防时序攻击）：
```js
import { scrypt, randomBytes, timingSafeEqual } from 'node:crypto'
function hashPassword(pw) {
  const salt = randomBytes(16).toString('hex')
  const derived = scrypt(pw, salt, 32).toString('hex')
  return `${salt}:${derived}` // 盐与密文同存
}
function verifyPassword(pw, stored) {
  const [salt, key] = stored.split(':')
  const derived = scrypt(pw, salt, 32)
  const keyBuf = Buffer.from(key, 'hex')
  return derived.length === keyBuf.length && timingSafeEqual(derived, keyBuf)
}
```
Token 用手写 HS256（base64url(header).base64url(payload).HMAC-SHA256），不引 `jsonwebtoken`。全局 `onRequest` 守卫统一拦截 `/api` 路由，放行 `/health`、登录、注册与静态资源。

### 3.3 测试隔离（一个真实踩过的坑）
早期测试把 `DB_PATH` 写成模块顶层 `const`：
```js
const DB_PATH = process.env.DB_PATH || 'data/app.db' // ❌ import 时就被快照
```
导致 `tests/setup.js` 里 `process.env.DB_PATH = ':memory:'` 在 import 之后才执行、**永不生效**，测试把用例写进了真实库——表现为「全部运行」出现一堆指向死链 `127.0.0.1:随机端口` 的 `fetch failed`。

修法：DB 路径改为 `getDb()` 内**惰性解析**，配合 `setupFiles` 在 import 前注入 `:memory:`，彻底隔离。这是测试可靠性的关键一役，也写进了 `TESTING.md`。

### 3.4 单端口部署
前端 `web/dist` 构建后由 Fastify 同源托管（`/*` 静态路由 + SPA 回退），部署只需一个端口、无跨域。提供 `Dockerfile`（node:22-alpine 多阶段）+ `docker-compose.yml`，挂卷 `/app/data` 持久化 SQLite。

### 3.5 用例链：让「需要登录的接口」真的能被自动测
最初的执行引擎一次只发一个请求 —— 登录拿到的 token 传不到下一个用例，于是**凡是需要鉴权的接口一条都测不了**。
补上的最小集合：

| 能力 | 做法 |
|---|---|
| 变量占位 | url / headers / body / 文件名里都能写 `{{token}}`，发请求前统一渲染 |
| 变量抽取 | 用例声明 `extract: [{ name: "rid", path: "$.id" }]`，从**本用例响应**里按 JSONPath 抽值 |
| 串链 | 「全部运行」按**创建顺序**跑，整轮共享一个变量袋（⚠️ 必须顺序，不能改成 `Promise.all`） |
| 分组 | `POST /api/run-all {"prefix":"OA-"}` 只跑一组 —— 平台里同时挂着打外网的示例用例，不分组会把别人的红算到自己头上 |

两个刻意的设计：
- **变量袋只在内存、不落库**：token 不该进数据库；也不该跨运行复用（否则会拿过期 token 假装通过）。
- **变量缺失不判失败**，但在 detail 里点名「未赋值变量：{{token}}」—— 缺变量时请求本来就会失败，两处都报会让人分不清真正原因。

配上一套真用例（office-oa 的 44 条）之后，平台终于能证明它是「能测真实系统的测试平台」，而不是「只能测自己 /health 的玩具」。

### 3.6 请求体类型与文件上传（手搓 multipart）
上一节补齐后还剩一条边界：执行器只会 `JSON.stringify(body)`，**发不出 `multipart/form-data`** ——
「上传文件」这件事平台压根做不到。这一条最初被我写进了「能力边界」，下一轮就当成工作项在**代码里**消掉了：

- `bodyTypes.js`：`json | raw | form-data` 白名单；`raw` 原样发字符串。
- `multipart.js`：手搓包体 —— `boundary` 生成、CRLF 与结尾 `--boundary--`、**二进制安全**、文件名字段引号转义 + 去换行。
- `fixtures.js`：内置夹具（PNG 41B / PDF 35B / 伪装 exe），**字节写进代码**而不是让用户传文件 ——
  自动化要的是「每次发一模一样的字节」，`size == 41` 这种断言才站得住。
- `runner.js`：form-data 时执行器**接管** `Content-Type`（带 boundary）与 `Content-Length`（用例手填的会被覆盖，大小写不敏感去重）。
- 夹具名写错**当场报错**，不静默发一个空文件 —— 那会让人以为「被测系统的上传接口有 bug」。

### 3.7 环境变量集：把「打谁」从用例里拿出来
原来被测地址只有 `BASE` 一个环境变量，而且**是在写用例时就被拼进 URL 的** ——
44 条 OA 用例的 url 里都烤着 `http://127.0.0.1:3200`，想打另一个环境就得重写整套用例。

改成：环境 = `{ name, baseUrl, headers, vars }`，用例里一律写 `{{base}}/api/xxx`，运行时按「当前环境」替换。
- **同一时刻只有一个当前环境**，存在 `settings` 表的**一行 KV** 里，而不是在 `environments` 上加 `is_active` 列 ——
  后者迟早会出现「两行都是 active」这种无法自证的状态。
- **优先级一：环境变量是基线，链上 `extract` 抽到的值优先。** 环境是「你去哪」，extract 是本次链上刚发生的事实；
  基线盖掉事实 = 用过期 token 假装通过。
- **优先级二：环境请求头是默认值，用例里手写的同名头优先**（大小写不敏感，否则请求里会同时出现 `Content-Type` 和 `content-type`）。
- `baseUrl` 保存时就归一化（去尾部斜杠 + 必须 http/https），把「地址写错」拦在保存时，而不是跑用例时给一句看不懂的 `fetch failed`。
- 三条运行路径（单跑 / run-all / 定时任务）都走 `runner.runCase`，环境只在**一处**生效，不会出现「手动跑用环境、定时跑不用」。

### 3.8 执行记录里的环境快照：配置是活的，历史是死的
3.7 把被测地址变成可配的，紧接着就冒出个新问题：报告里只有通过率，**答不出这次跑在哪个环境**。
地址写死的年代这不是问题（只有一个地址），地址一变可配，**每条不写清「当时用的是哪个值」的历史记录就都不可解释了**。

修法就一句：`runs` 表**存快照**，不只存外键。
- `env_name` + `base_url` 存的是**执行当时**的值；只存 `env_id` 的话，地址改一次（本地 → 预发），
  历史记录就被**反向改写**成「它从没打过的地址」。
- 报告新增「**按运行环境汇总**」，分组键就是这份快照 → 地址改过之后自然分成两组，「换个环境就全红」一眼可见；
  混在一起算平均值只会掩盖它。
- 老记录（升级前跑的）归到「(未记录环境)」一组，**不编造**环境名 —— 本机实测 557 条，
  这本身就是迁移的留痕。
- 这与 office-oa 的 `flow_snapshot`（改流程模板不影响在途单据）是**同一条教训**：**配置是活的，历史是死的。**

## 5. 简历话术（可直接抄）

- **独立设计并实现一个 API 自动化测试平台**（Fastify + Vue3 + Node 内置 SQLite），覆盖用例管理、多维度断言、定时任务、报告、账号体系与环境变量集，已容器化部署，**113 个单元测试全绿**。
- 自研 **JSONPath 断言求值器**、**零依赖鉴权模块**（scrypt 哈希 + 手写 HS256 JWT）与 **multipart 包体生成器**，全程**不引入任何原生编译或第三方表单库**，保证跨平台与 CI 零编译坑。
- **实现用例链（变量渲染 + JSONPath 抽取 + 按创建顺序串链）**，使「需要登录的接口」也能被自动化覆盖；并用这套平台**把自己写的另一个系统 office-oa 测穿**（44 条用例串成一条业务链，44/44 通过）。
- **设计环境变量集**，把被测地址从 44 条用例里抽出来（用例写 `{{base}}`），并让「当前环境」在三处可见、一处可切，换环境不再需要重写用例；**执行记录改存环境快照**，使报告在环境地址变更后仍可解释（配置是活的，历史是死的）。
- 设计 **test/prod 数据库隔离方案**，修复了 ESM 模块顶层快照环境变量导致测试污染生产库的隐患。
- 实现 **单端口前后端同部署**，前端构建产物由后端同源托管，降低部署复杂度。

## 6. 踩坑记录（复盘价值）

1. **ESM 环境变量快照**：见 3.3，测试污染真实库。
2. **鉴权守卫误伤静态资源**：守卫最初只放行 `/health` 与登录/注册，导致生产环境前端路由（如 `/reports`）也被返回 401、登录页白屏。改为「非 `/api` 路径一律公开」并加回归测试。
3. **Windows 直接运行静默退出**：`import.meta.url === file://${process.argv[1]}` 在 Windows 反斜杠路径下恒假，改用 `pathToFileURL(process.argv[1]).href` 判断是否为直接运行。
4. **断言引擎的语义坑（拿真系统测出来的）**：用例要断言「权限数组里有 `user:read`」，写 `$.permissions[*]` + `contains` ——
   结果**假失败**，因为引擎的多匹配 `contains` 只看**第一个**匹配值（数组第一个是 `announcement:write`）。
   改成「**任一**命中即通过」，提示改成「匹配 N 个，首个 X」。⭐ **红的是我的工具，不是被测系统** —— 分开归因很重要。
5. **变量缺失的提示被异常分支吃掉了**：`{{base}}` 没赋值 → 渲染成空串 → url 变成 `/whoami` → `fetch` 直接抛错 → 走 catch 分支，
   而那段代码只写了 `detail: [e.message]`，**把「谁没赋值」这条最有用的线索丢在成功分支里了**。
   修法：把「未赋值变量」的计算提到发请求**之前**，catch 分支也带上它。⭐ **最需要提示的人，恰好是收不到提示的人。**
6. **一个会撒谎的环境徽标**：给页头加了「当前环境」徽标之后，真机点了一遍才发现 ——
   在环境页里点「取消当前环境」，**页头徽标纹丝不动**。原因是徽标画在 `App.vue`（外壳）、切环境发生在 `Environments.vue`（子页面），
   两处各读各的状态，靠「路由变化时重取」对齐；而**在同一页里切环境根本不引起路由变化**。
   修法：把当前环境抽成共享的 reactive 状态（`web/src/env.js`，与 `auth.js` 的 `session` 同一套路），谁改谁 set。
   ⭐ **一个会撒谎的状态显示，比没有这个显示更危险** —— 徽标写着「打测试环境」而平台其实在打别的地址，比不显示环境名更容易让人犯错。
7. **Vue 路由复用组件导致的表单串味**：从 `/cases/1/edit` 切到 `/cases/new`，vue-router **复用同一个组件实例**、`onMounted` 不重跑，
   于是新建页里残留着上一条用例的 `bodyType=form-data`，**凭空显示出「文件字段」**。
   修法：`resetForm()` + `watch(() => id, load)`。⭐ 这类 bug 单测抓不到、`vite build` 也不报错（Vue 对未声明标识符只 warning），**只有真机走一遍才露头**。
8. **把值从「固定」改成「可配」，顺带挖了个可观测性的坑**：见 3.8。地址写死时报告不需要说地址，
   一旦地址可切换，「不记录当时用的是哪个值」的历史就全部不可解释 —— 一个跨了两个环境的 92% 通过率，什么都不能说明。
   修法是把快照写进执行记录，而不是「显示得更清楚」。⭐ **配置是活的，历史是死的。**

## 7. 怎么跑起来
```bash
npm install && cd web && npm install && cd ..
npm run dev        # 后端 :3001 + 前端 :5173
npm run seed       # 写入示例用例（首次打开就有东西可跑）
# 打开 http://localhost:5173 → 用 admin/admin123 登录 → 全部运行
npm test           # 113 例全绿

# —— 用这个平台去打 office-oa（闭环）——
cd ../office-oa && node seed.js --force && node index.js   # OA 在 3200 上跑
cd ../api-test-platform
npm run seed:oa    # 写入 44 条 OA 用例，并定义 + 选中「当前环境」
npm run test:oa    # 44/44；任一条失败以非 0 退出，可挂 CI
node scripts/m10-report-env-check.mjs   # 从报告接口读回「这一轮实际打的是哪个环境」
```
部署：`docker compose up -d --build` → 访问 `http://<服务器IP>:3001`。
